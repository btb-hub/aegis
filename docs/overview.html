Ops & incident management · build-ready spec

One place to run on-call, catch incidents, and see who's holding the pager.

Aegis takes a firing alert, turns it into one owned incident, opens a Jira ticket, and pages the person who's actually on call right now, across Slack and eXpress. Sign in with Google, Slack, or eXpress OIDC. The web UI and chat pages ship in English and Russian. This is the documentation an AI agent team builds from, story by story.

01

The three north stars

Every decision answers to these. They come straight from the IT department's point of view, and the analytics and setup work is measured against them.

EASY TO

Set up

One .env, one docker compose up, then a guided web wizard. Clean host to first routed alert in under one working day.

EASY TO

Use

One screen per job: who's on call, the alert workspace, the incident timeline. Ack from a chat button. L2 hands off to L3 in a single click.

EASY TO

Analyse

Five questions answered in-product without a spreadsheet: are we faster, what's noisy, is load fair, how's L2 to L3, how are we escalating.

02

The four MVP features

Mandatory for the first release. Each has a deep spec and a dedicated epic.

PRD §1

Shifts calendar

Set up rotations per team and get a correct answer to "who's on call right now", including daylight-saving edges and one-off overrides. On-call is materialised so reads are instant.

feature spec EPIC-02 · 7 stories
PRD §2

Incident management

A firing alert is deduped, routed to a team, assigned to its current on-call, gets a Jira ticket created automatically, and pages everyone who needs to know. Full lifecycle with a timeline, acknowledge, and escalation timers.

feature spec EPIC-04 · 11 stories
PRD §3

Alerting workspace

Filter, search, and group across a large alert history without it crawling. Save the views you reopen daily, read inline analytics on the current slice, export to CSV.

feature spec EPIC-05 · 8 stories
PRD §4

L2 to L3 transparency

L2 hands an incident to the right L3 on-call in one action: it reassigns, links Jira, and pages them. Both levels see one identical timeline, and every handoff is analysable down to time-to-first-L3-response.

feature spec EPIC-06 · 5 stories
03

Architecture at a glance

The request path stays fast and dumb: validate, store, enqueue, return. All the real work (dedup, routing, ticket creation, paging, escalation) happens in the worker.

monitoring -> [ API (Go) ] -> validate + store alert + insert job -> 202 | v [ Postgres ] | v [ Worker (Go) ] -> dedup / group -> route to team -> create incident | | v v assign on-call create Jira ticket | | +------------------+------------------+ v fan-out: Slack / eXpress | ack <-+-> escalate (timer)

apps/api

Go/Gin. OIDC auth, CRUD, alert intake, callbacks, analytics reads. Returns 202 fast and gets out of the way.

apps/worker

Postgres job poller. Dedup, routing, incident + ticket creation, paging, escalation timers, on-call materialisation.

apps/web

React + TypeScript + Vite, Tailwind, Recharts. Wizard, calendar, alert workspace, incident view, dashboards.

data

PostgreSQL 16 only (JSONB labels with GIN, full-text search, jobs table). golang-migrate. Docker Compose for the MVP.

Full detail in 02-architecture, 03-data-model, and 04-api-spec.

04

Integrations

Each connector implements a shared interface, so the rest of Aegis doesn't care which ones are on. Any subset works; a failing one degrades gracefully. All outbound calls run in the worker with retry and idempotency.

Ticket
Jira

Auto-creates and links the incident ticket, syncs status back. REST v2/v3.

Chat
Slack

Block Kit messages, Acknowledge button, signed callbacks. Also OIDC sign-in.

Chat
eXpress

BotX HTTP API, HMAC token, bubbles, /link bootstrap. Also OIDC sign-in.

Per-connector specs in docs/integrations. Auth in 09-security (Google + Slack + eXpress OIDC). Stories in EPIC-03 (5 stories).
