# Соберите процесс, чтобы у алерта был владелец.

Идите по экранам по порядку. Сквозной пример — проект **Platform**: L2
принимает пэйдж, L3 принимает передачу. Нужна роль **Администратор** (смотрите
**Аккаунт** в шапке). Участник и наблюдатель команды, графики и правила создать не могут.

[Вход](#signin) | [Рабочая область](#workspace) | [Команды](#teams) | [Участники](#members) | [Эскалация](#path) | [Смены](#shifts) | [Маршрутизация](#routing) | [Правила (примеры)](routing.md) | [Пути (примеры)](paths.md) | [Тестовый алерт](#prove)

<a id="signin"></a>

## 01 · Войдите как администратор

Страница входа одна на всех. Что можно менять, зависит от роли в аккаунте, а
не от кнопки провайдера.

1. **Откройте приложение и выберите провайдера**
   Страница входа: **Google**, **Slack** или **eXpress**. После редиректа вы в приложении.

2. **Проверьте, что вы администратор**
   Шапка → **Аккаунт**. Бейдж роли — **Администратор**. Если «Участник» или
   «Наблюдатель», это руководство не закончить: попросите админа повысить вас в
   **Пользователи**.

> **Сначала люди должны войти, потом вы добавите их в команду**
>
> Aegis не приглашает по почте. Каждый дежурный входит один раз, затем вы жмёте
> **Добавить участника**. Для пэйджа в Slack нужен вход через Slack. eXpress — привязка в
> **Аккаунт**, см. [связь](connect.md#paging).

<a id="workspace"></a>

## 02 · Создайте рабочую область

Рабочая область — проект. В ней команды, правила маршрутизации и в какой
проект Jira падают тикеты. В одном Aegis может быть несколько областей (Platform и Data рядом).

1. **Сайдбар → Рабочие области**
   **Создать рабочую область**. **Название** — например Platform. Slug необязателен.
   **Сохранить**.

2. **Откройте область**
   На карточке потом будут команды, интеграции и правила. Вернётесь к правилам, когда
   появятся команды.

> **Короткий путь: Мастер → Быстрая настройка**
>
> В **Мастер настройки** пункт **Быстрая настройка (новый проект)** создаёт область, L2, L3
> и путь L2→L3 сразу. Дальше — [участники](#members) и [смены](#shifts).

<a id="teams"></a>

## 03 · Создайте команды и задайте уровни

Уровень поддержки живёт на **команде**, не на человеке. Он определяет,
какие кнопки эскалации будут на инциденте.

| Уровень | Типичное имя | Роль в цепочке |
| --- | --- | --- |
| NOC | Platform NOC | Первый взгляд на мониторинг; эскалация в L1 или L2 |
| L1 | Хелпдеск | Пользовательские обращения; эскалация в L2 |
| L2 | Platform L2 | Большинство продовых инцидентов; передача в L3 |
| L3 | Platform L3 | Специалисты; могут вернуть в L2 с комментарием |

1. **Сайдбар → Команды → Создать команду**
   Название **Platform L2**. **Рабочая область** — Platform. **Уровень поддержки** —
   **L2**. Сохранить. Повторите для **Platform L3** с уровнем **L3**.

Минимум: одна L2 и одна L3 в
одной области. NOC и L1 добавите, если так устроен разбор.

<a id="members"></a>

## 04 · Добавьте участников

Участники попадают в ротацию и могут быть назначены, когда команда владеет
инцидентом.

1. **Откройте команду L2**
   Блок **Участники** → **Добавить участника**. Поиск по имени или email. Роль
   **Участник** или **Лид** (лид не заменяет администратора).

> **Пустой поиск людей**
>
> Значит, они ещё ни разу не входили. Попросите открыть вход один раз, затем снова
> **Добавить участника**.

<a id="path"></a>

## 05 · Разрешите L2 передать в L3

Бейджа уровня мало. Путь добавляют на команде, которая нажмёт кнопку.
Развёрнутые примеры: [пути эскалации](paths.md).

1. **Команды → Platform L2 → Пути эскалации**
   Откройте **исходную** команду (L2), не L3. **Исходящие пути** → **Добавить путь**.

2. **Заполните форму**
   #### Добавить путь · команда **Platform L2**

| Поле | Значение |
|-------|-------|
| Разрешить команду из другой области | Выкл. |
| В команду | Platform L3 |

Сохраните. У L2 в исходящих — Platform L3. У Platform L3 во входящих —
Platform L2. На инциденте L2 появится **Передать в L3**.

Только пары: NOC→L1 или L2,
L1→L2, L2→L3. Пустой список — нет L3 или не задан уровень, см.
[пустой пикер](paths.md#empty).

<a id="shifts"></a>

## 06 · Поставьте кого-то на смену

Маршрутизация отдаёт инцидент команде. Пэйдж уходит текущему дежурному. Без
графика инцидент может появиться, но пэйджить некого.

1. **Смены команды L2**
   Сайдбар **Смены** → Platform L2. Если видите **У этой команды пока нет графика дежурств** —
   продолжайте.

2. **Создать график**
   **Создать график**: название, **Часовой пояс (IANA)** (например
   `Europe/Moscow`), **День передачи смены**, **Время передачи смены**,
   **Участники (порядок ротации)**. **Сохранить график**.

3. **Проверьте «Сейчас на смене»**
   Баннер должен назвать человека. Если **Сейчас никто не дежурит** — ротация не
   покрывает этот момент: **Добавить подмену** на сегодня или поправьте день/время передачи.

<a id="routing"></a>

## 07 · Направьте алерты в команду L2

Правило создают на **рабочей области**: Рабочие области → Platform →
**Правила маршрутизации** → **Добавить правило**. Одна форма = одно совпадение метки.
Больше примеров: [правила маршрутизации](routing.md).

#### Добавить правило · область **Platform**

| Поле | Значение |
|-------|-------|
| Разрешить команду из другой области | Выкл. |
| Целевая команда | Platform L2 |
| Ключ метки | `team` |
| Значение метки | `platform` |
| Приоритет | `100` (большее число проверяется первым, если подошли два правила) |

Grafana/Alertmanager должен прислать именно эту пару (регистр важен). Лишние
метки не мешают. Алерты есть, инцидентов нет — скопируйте ключ и значение с карточки алерта
в эту форму.

URL вебхука:
`{адрес Aegis}/api/v1/alerts/webhook`. Новые алерты не направляйте сразу в L3 —
L3 получает работу по пути, не из этого правила.

<a id="prove"></a>

## 08 · Проверьте цепочку

Коннекторы для этой проверки не обязательны. Тикеты и пэйджи —
[подключение Jira, Slack, eXpress](connect.md).

1. **Отправить тестовый алерт**
   Сайдбар **Мастер настройки** → **Тестовый алерт** → **Отправить тестовый алерт**.
   Должен быть тост с id алерта.

2. **Откройте Инциденты**
   Новый инцидент у Platform L2, назначен на того, кого показал баннер. В карточке —
   лента, связанный алерт и (если подключено) ссылка Jira.

> **Первый проект готов, когда**
>
> У каждой пэйджинговой команды график покрывает «сейчас». У каждой области есть хотя бы одно
> правило. У L2 есть путь на L3. Если нужны Jira и чат — **Проверить подключение** на
> **Интеграции** прошло.

### Потом добавите второй проект

- **Рабочие области** → Создать **Data**.
- Команды **Data L2** и **Data L3** с нужными уровнями.
- На Data L2 путь в Data L3.
- Правило: `project=data` → Data L2.
- В области Data Jira: наследовать глобальное, ключ проекта `DATA`.
- График Data L2.
