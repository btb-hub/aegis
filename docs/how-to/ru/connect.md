# Подключите Jira, Slack и eXpress в интерфейсе.

Тикет и пэйдж не обязательны, чтобы инцидент существовал, но так работу видит
остальная компания. Настраивайте на **Интеграции** и на каждой рабочей области. Мастер не
нужен, чтобы сменить один секрет.

## 01 · Глобальные коннекторы

Сайдбар → **Интеграции**. Это значения по умолчанию, которые области могут
наследовать.

1. **Jira**
   **Добавить интеграцию** или **Настроить**. Выберите **Server / Data Center** или **Cloud**
   отдельно от типа авторизации. Для Server/DC обычно нужен **Bearer** с PAT, для Cloud
   **Basic** с email и API-токеном. Укажите базовый URL (включая путь Jira) и ключ проекта.
   **Сохранить**, затем **Проверить подключение**. Проверка подтверждает только авторизацию;
   отправьте алерт с подходящим маршрутом, чтобы проверить создание, назначение и видимость тикета на доске.

2. **Slack**
   Нажмите **Настроить Slack** в карточке бота. Установите приложение Slack с `chat:write`,
   сохраните **Bot User OAuth Token** и **Signing Secret**. Включите **Interactivity** и укажите
   показанный Request URL: `https://<public-aegis-origin>/api/v1/callbacks/slack/interactive`.
   Slack должен иметь HTTPS-доступ к нему. **Проверить подключение** проверяет токен;
   доставку и кнопку **Принять** проверяйте реальным сообщением. ЛС идут привязанному
   пользователю, объявления в канал команды, куда добавлен бот. Сохранённые секреты действуют
   без перезапуска API. Настройка бота отделена от входа через Slack.

3. **eXpress**
   Сохраните ID бота, хост CTS и секрет, затем **Проверить подключение**. Задайте глобальный
   **ID группового чата дежурств eXpress** для объявлений и обновлений инцидентов. Добавьте
   бота в группу. Дежурные подключают eXpress в **Аккаунт → Мессенджеры для пейджинга**
   и открывают личный чат с ботом для персональных пэйджей.

## 02 · Слоты рабочей области

У каждой области слоты Jira, Slack и eXpress. Откройте область → **Интеграции**.

| Режим | Когда |
| --- | --- |
| **Наследовать** | Глобальный коннектор. У Jira можно свой ключ проекта (Platform →<br>`OPS`, Data → `DATA`), у Slack свой канал. Возврат к этому режиму удаляет секреты слота рабочей области. |
| **Собственные** | Полные свои учётные данные, без смешивания с глобальными. |

В слоте Slack нажмите **Настроить глобальный Slack**, чтобы изменить общий бот. Для отдельного
бота выберите **Собственные** и сохраните токен и Signing Secret. Команды используют бот своей
рабочей области. Сохранять секреты и проверять подключения может только администратор.

## 03 · Кого пэйджить — в Аккаунте

- Каждый дежурный открывает **Аккаунт → Мессенджеры для пейджинга** и нажимает **Подключить**
  для Slack или eXpress. Завершите авторизацию в браузере и вернитесь в Аккаунт. Команда боту
  и ручной ввод ID не нужны. Подключение уведомлений не добавляет провайдер входа.
- **Заменить** сохраняет прежнее подключение до успешной авторизации. **Отключить** требует
  подтверждения и прекращает пэйджи через этот мессенджер, сохраняя способы входа.
- Если подключение недоступно, администратор должен настроить OIDC провайдера и включить
  глобальный бот. Slack должен соответствовать рабочему пространству глобального бота;
  eXpress SSO должен передать подтверждённый email ровно одного активного пользователя мессенджера.
- Язык **English** / **Русский** тоже здесь; персональные пэйджи и приватные результаты
  действий в чате идут на языке получателя.

Требования для администратора и совместимость старого API: [Подключение мессенджеров](../../features/paging-connections.md).

### Общие каналы и проверка доставки

На странице команды задайте **ID канала Slack** и, при необходимости, **ID тега команды Slack** (ID группы пользователей).
Бот рабочей области должен иметь доступ к каналу. Общие сообщения eXpress идут в **глобальный**
чат дежурств, даже если персональные пэйджи используют отдельные настройки области.

Создайте тестовый инцидент через маршрут и проверьте тикет Jira, личный пэйдж и общий пост.
Нажмите **Принять** в чате, дождитесь приватного результата, затем закройте инцидент в Aegis
и проверьте обновление канала. Создание, подтверждение, закрытие и эскалация дают отдельные
посты; передача и возврат в эту функцию не входят. Worker должен работать.

## 04 · Нет коннектора — инцидент всё равно будет

Если Jira или чат не готовы, алерт и инцидент всё равно создаются. В ленте
событие `integration_skipped`. Почините слот, не пересылайте вебхук без нужды —
получите дубль алерта.
