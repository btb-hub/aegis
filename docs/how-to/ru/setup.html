Админ · первый проект

Соберите процесс, чтобы у алерта был владелец.

Идите по экранам по порядку. Сквозной пример — проект Platform: L2 принимает пэйдж, L3 принимает передачу. Нужна роль Администратор (смотрите Аккаунт в шапке). Участник и наблюдатель команды, графики и правила создать не могут.

01

Войдите как администратор

Страница входа одна на всех. Что можно менять, зависит от роли в аккаунте, а не от кнопки провайдера.

Откройте приложение и выберите провайдера

Страница входа: Google, Slack или eXpress. После редиректа вы в приложении.

Проверьте, что вы администратор

Шапка → Аккаунт. Бейдж роли — Администратор. Если «Участник» или «Наблюдатель», это руководство не закончить: попросите админа повысить вас в Пользователи.

Сначала люди должны войти, потом вы добавите их в команду

Aegis не приглашает по почте. Каждый дежурный входит один раз, затем вы жмёте Добавить участника. Для пэйджа в Slack нужен вход через Slack. eXpress — привязка в Аккаунт, см. связь.

02

Создайте рабочую область

Рабочая область — проект. В ней команды, правила маршрутизации и в какой проект Jira падают тикеты. В одном Aegis может быть несколько областей (Platform и Data рядом).

Сайдбар → Рабочие области

Создать рабочую область. Название — например Platform. Slug необязателен. Сохранить.

Откройте область

На карточке потом будут команды, интеграции и правила. Вернётесь к правилам, когда появятся команды.

Короткий путь: Мастер → Быстрая настройка

В Мастер настройки пункт Быстрая настройка (новый проект) создаёт область, L2, L3 и путь L2→L3 сразу. Дальше — участники и смены.

03

Создайте команды и задайте уровни

Уровень поддержки живёт на команде, не на человеке. Он определяет, какие кнопки эскалации будут на инциденте.

УровеньТипичное имяРоль в цепочке
NOCPlatform NOCПервый взгляд на мониторинг; эскалация в L1 или L2
L1ХелпдескПользовательские обращения; эскалация в L2
L2Platform L2Большинство продовых инцидентов; передача в L3
L3Platform L3Специалисты; могут вернуть в L2 с комментарием

Сайдбар → Команды → Создать команду

Название Platform L2. Рабочая область — Platform. Уровень поддержки — L2. Сохранить. Повторите для Platform L3 с уровнем L3.

Минимум: одна L2 и одна L3 в одной области. NOC и L1 добавите, если так устроен разбор.

04

Добавьте участников

Участники попадают в ротацию и могут быть назначены, когда команда владеет инцидентом.

Откройте команду L2

Блок Участники → Добавить участника. Поиск по имени или email. Роль Участник или Лид (лид не заменяет администратора).

Пустой поиск людей

Значит, они ещё ни разу не входили. Попросите открыть вход один раз, затем снова Добавить участника.

05

Разрешите L2 передать в L3

Бейджа уровня мало. Путь добавляют на команде, которая нажмёт кнопку. Развёрнутые примеры: пути эскалации.

Команды → Platform L2 → Пути эскалации

Откройте исходную команду (L2), не L3. Исходящие пути → Добавить путь.

Заполните форму

Добавить путь · команда Platform L2
Разрешить команду из другой области
Выкл.
В команду
Platform L3

Сохраните. У L2 в исходящих — Platform L3. У Platform L3 во входящих — Platform L2. На инциденте L2 появится Передать в L3.

Только пары: NOC→L1 или L2, L1→L2, L2→L3. Пустой список — нет L3 или не задан уровень, см. пустой пикер.

06

Поставьте кого-то на смену

Маршрутизация отдаёт инцидент команде. Пэйдж уходит текущему дежурному. Без графика инцидент может появиться, но пэйджить некого.

Смены команды L2

Сайдбар Смены → Platform L2. Если видите У этой команды пока нет графика дежурств — продолжайте.

Создать график

Создать график: название, Часовой пояс (IANA) (например Europe/Moscow), День передачи смены, Время передачи смены, Участники (порядок ротации). Сохранить график.

Проверьте «Сейчас на смене»

Баннер должен назвать человека. Если Сейчас никто не дежурит — ротация не покрывает этот момент: Добавить подмену на сегодня или поправьте день/время передачи.

07

Направьте алерты в команду L2

Правило создают на рабочей области: Рабочие области → Platform → Правила маршрутизации → Добавить правило. Одна форма = одно совпадение метки. Больше примеров: правила маршрутизации.

Grafana/Alertmanager должен прислать именно эту пару (регистр важен). Лишние метки не мешают. Алерты есть, инцидентов нет — скопируйте ключ и значение с карточки алерта в эту форму.

URL вебхука: {адрес Aegis}/api/v1/alerts/webhook. Новые алерты не направляйте сразу в L3 — L3 получает работу по пути, не из этого правила.

08

Проверьте цепочку

Коннекторы для этой проверки не обязательны. Тикеты и пэйджи — подключение Jira, Slack, eXpress.

Отправить тестовый алерт

Сайдбар Мастер настройки → Тестовый алерт → Отправить тестовый алерт. Должен быть тост с id алерта.

Откройте Инциденты

Новый инцидент у Platform L2, назначен на того, кого показал баннер. В карточке — лента, связанный алерт и (если подключено) ссылка Jira.

Первый проект готов, когда

У каждой пэйджинговой команды график покрывает «сейчас». У каждой области есть хотя бы одно правило. У L2 есть путь на L3. Если нужны Jira и чат — Проверить подключение на Интеграции прошло.

Потом добавите второй проект

  1. Рабочие области → Создать Data.
  2. Команды Data L2 и Data L3 с нужными уровнями.
  3. На Data L2 путь в Data L3.
  4. Правило: project=data → Data L2.
  5. В области Data Jira: наследовать глобальное, ключ проекта DATA.
  6. График Data L2.
Дальше: работа с инцидентом или подключить Jira и чат.
