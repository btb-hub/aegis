# Как настроить процесс дежурств.

Это руководство по продукту: что нажимать в Aegis, чтобы сработавший алерт
стал чужим инцидентом, тикетом в Jira и пэйджем человеку, который сейчас на смене. Это не
инструкция по установке. Процесс настраивает **администратор**; дежурные читают
[Работу с инцидентом](incidents.md).

## 01 · Что вы собираете

Рабочая область — это проект (Platform, Data, Payments). Команды в ней
принимают пэйджи. Правило маршрутизации решает, какая команда владеет новым алертом. Пути
эскалации решают, куда L2 может передать работу.

```
мониторинг  →  алерт (метки)  →  правило маршрутизации  →  инцидент
                                              │
                                              ├─ назначить текущего дежурного целевой команды
                                              ├─ открыть тикет Jira (если Jira подключена)
                                              └─ пэйдж в Slack / eXpress (если подключены)

дежурный  →  Принять  →  (по желанию) Передать в L3  →  Закрыть
```

Пока нет правила, графика и
хотя бы одной команды, алерты могут появиться в **Алертах** и не стать инцидентом. Так и
задумано.

<a id="pick"></a>

## 02 · Выберите задачу

Новый проект начинайте с настройки. Остальные страницы предполагают, что
процесс уже собран.

- **[Настроить процесс](setup.md)** — *Админ · первый раз*. Вход, рабочая область, команды L2 и L3, участники, путь эскалации, недельная ротация,
правило маршрутизации, тестовый алерт.
- **[Правила маршрутизации с примерами](routing.md)** — *Админ · совпадения*. Заполненные формы: одно правило Platform, два проекта, NOC и L2 по приоритету, общий
DevOps. Большее число приоритета проверяется первым.
- **[Пути эскалации с примерами](paths.md)** — *Админ · передача*. Добавить путь на исходной команде. L2→L3, NOC→L1→L2→L3, Data L2 через Platform L3.
Почему нет кнопки «Передать».
- **[Работа с инцидентом](incidents.md)** — *Дежурный*. Принять из Slack, eXpress или веба. Разобрать, передать в L3, вернуть, закрыть. Одна
лента событий для всех уровней.
- **[Подключить Jira, Slack, eXpress](connect.md)** — *Админ · коннекторы*. Глобальные учётные данные, Проверить подключение, затем наследовать или свои слоты на
рабочей области.
- **[Если процесс неполный](troubleshooting.md)** — *Застряли*. Алерты без инцидентов, пустой «Сейчас на смене», нет кнопки передачи, никто не получает
пэйдж.

<a id="order"></a>

## 03 · Порядок, который работает

Идите по шагам. Если перескочить, алерты не станут инцидентами, а у кнопки
передачи не будет целей.

1. **Рабочая область** — Граница проекта для команд и правил.
2. **Команды и уровни** — L2 принимает пэйдж. L3 — цель передачи.
3. **Участники и смены** — Кто-то должен дежурить, когда придёт алерт.
4. **Маршрутизация** — Метка (например `team=platform`) → L2.
5. **Связь и проверка** — Jira / чат, затем **Отправить тестовый алерт**.

> **Мастер настройки необязателен**
>
> Пункт **Мастер настройки** в сайдбаре — чеклист. Для одной правки лучше страницы
> **Рабочие области**, **Команды**, **Смены**, **Интеграции**.
> **Быстрая настройка (новый проект)** создаёт область, L2, L3 и путь L2→L3 одним шагом.
